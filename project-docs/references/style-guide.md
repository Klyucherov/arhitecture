# Style Guide — правила оформления генерируемых документов

Применяется ко всем трём выходным файлам (`ARCHITECTURE.md`, `TESTING.md`, `AGENTS.md`).

## 1. Язык и терминология

- Русский язык; идентификаторы, команды, сообщения логов, названия технологий — в оригинале (`FastAPI`, `start-process`, `document_processing`).
- Один термин — одно слово во всех документах: выбрал «пакет документов» — не пиши «набор» и «батч».
- Технологии писать в общепринятом регистре: `PostgreSQL`, `Kafka`, `FastAPI`, `Docker`.
- Факты без оценок: «сервис делает X», а не «удобный/надёжный сервис».
- Без воды: каждое предложение несёт проверяемый факт.

## 2. Структура markdown

- Заголовки нумерованы (`## 3. Высокоуровневая архитектура`), подразделы — `### 3.1.` и т.д.
- После заголовка первого уровня — блок `>` с версией, датой, назначением.
- Разделители `---` между разделами верхнего уровня.
- «Содержание» со ссылками-якорями обязательно в `ARCHITECTURE.md` и `TESTING.md`.
- Пути к коду — в обратных кавычках: `src/services/pipeline.py`. При упоминании компонента давать файл-источник.

## 3. Mermaid-конвенции

Обязательные правила (нарушение ломает рендер):

- ID узлов — без пробелов, camelCase/PascalCase/подчёркивания: `BatchWatchdog`, `ocr_client`. Плохо: `Batch Watchdog`.
- Не использовать зарезервированные слова как ID: `end`, `graph`, `subgraph`, `flowchart`.
- Подписи со спецсимволами (скобки, запятые, двоеточия, слэши) — в двойных кавычках: `A["Обработка (main)"]`, `A -->|"O(1) lookup"| B`.
- Никаких стилей и цветов: запрещены `style`, `classDef`, `:::`. Тема рендерится автоматически.
- `click` не использовать.
- Subgraph — только с явным ID: `subgraph app ["Сервис (один процесс)"]`.
- Многострочные подписи — через `\n` внутри кавычек.

Типы диаграмм по назначению:

| Задача | Тип |
|---|---|
| Общая архитектура, потоки данных | `flowchart TB` (или `TD`) |
| Ветвления логики, обработка ошибок | `flowchart TD` с ромбами `{условие}` |
| Взаимодействие во времени (webhook, async) | `sequenceDiagram` |
| Схема БД | `erDiagram` (PK/FK, связи `\|\|--o{`) |
| Статусные модели | `stateDiagram-v2` |

После каждой диаграммы — 1-2 абзаца текста с тем, что диаграмма не показывает: мотивация, инварианты, защита от гонок.

## 4. Таблицы

- Заголовок таблицы — существительные, без точек.
- Пустых ячеек быть не должно: нет данных — нет строки; нет строк — нет раздела.
- Код, пути, статусы, методы — в обратных кавычках: `` `POST` ``, `` `WAIT_OCR` ``.
- Главные строки (основные endpoints, ключевые таблицы) допустимо выделять жирным.

## 5. Безопасность (закрытый контур)

Не переносить в документы:

- пароли, токены, ключи, строки подключения с креденшелами;
- реальные внутренние хосты и IP — заменять на `<host Kafka>`, `<URL ECM>`;
- персональные данные из примеров и фикстур;
- содержимое `.env` (можно — имена переменных из `.env.example` и кода).

## 6. Даты и версии

- Дата — формат `YYYY-MM-DD`.
- Версия — из манифеста (`pyproject.toml`, `package.json`, тег). Неизвестна — писать `не указана`, не выдумывать.
